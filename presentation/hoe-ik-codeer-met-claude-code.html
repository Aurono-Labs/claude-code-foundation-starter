Probleem

Lange projecten drijven af.

Aurono Labs

Een weekendprojectje overleeft zonder structuur. Een echt product niet. Na honderden sessies raak je samenhang kwijt: in woorden, in scope, in ontwerpkeuzes — en in wat 'klaar' eigenlijk betekent.

Vocabulaire
"Trade" ≠ "Order" ≠ "Fill"
Twee engineers die hetzelfde woord voor andere dingen gebruiken — daar begint de erosie.
Scope
Fase 2 lekt door in Fase 1
Zonder roadmap lijkt elk glimmend idee de volgende sprint waard.
Kwaliteit
'Klaar' zonder tests
Zonder werkproces belanden er om 23:00 commits in master — zonder enige functionele check.

De oplossing is geen slimmer model. Het is een geschreven fundament waar het model elke sessie op terugvalt.

Laag 3

De vastgelegde taal.

Aurono Labs
→docs/domain_terminology.md →docs/non_goals.md

De regel

Termen leg je één keer vast. Nooit hernoemen. Nooit met dubbele betekenis. Verschijnt er een nieuw begrip? Dan kies je een nieuw woord.

Woorden zijn infrastructuur.

  • Decision ≠ Intent ≠ Trade ≠ Order ≠ Fill
  • Reservation ≠ Allocation. Het non-goals-bestand zegt wat we expliciet níét doen.
  • De prijs: 20 minuten, eenmalig. De winst: weken zonder dubbelzinnigheid in code, events, UI, docs.

De methode

Per laag: voer een gesprek.

Aurono Labs

Gooi deze bestanden niet zomaar in je repo en hoop er het beste van. Werk ze stuk voor stuk door met Claude Code, totdat ze sterk genoeg zijn om slechte ideeën zelf af te wijzen.

1

Samen lezen

"Lees vision_and_mission.md. Vertel me waar dit ons aan bindt."

2

Stresstest het

Stel een slecht idee voor. Kijk of het terugduwt. Zo niet, dan is het document niet sterk genoeg — herschrijf het.

3

Leg het vast

Voeg een zin toe aan CLAUDE.md: "al het werk moet kloppen met X, gedefinieerd in <bestand>."

4

Door naar de volgende laag

Visie → Roadmap → Terminologie → Plan → Design → Tests → Workflow.

Totale tijd: ongeveer twee uur geconcentreerd gesprek per project. Verdient zich binnen een week terug.

De voorbeelden in deze presentatie zijn in het Engels — afkomstig uit Aurono Start, de referentie-implementatie. Je eigen fundament kun je in elke taal opzetten (Engels, Nederlands of beide); Claude Code volgt de taal van je CLAUDE.md en docs/.

Wat verder

Skills — instructies op afroep.

Aurono Labs

Een skill is een markdown-pakket met YAML-frontmatter dat Claude Code automatisch laadt zodra zijn trigger afgaat. Conditioneel dus — anders dan CLAUDE.md, dat altijd in context staat.

Wat ze toevoegen

  • Conditioneel laden — alleen actief als de trigger past. Minder ruis, scherpere aandacht.
  • Handhaving boven uitspraak — diff scannen, regels weigeren, niet alleen "denk eraan."
  • Slash commands i.p.v. fragiele triggerzinnen — eenduidig, met autocomplete en validatie.

Voorbeeld: zes triggerzinnen, zes commands

"Nieuw idee: …"/idee "Op de backlog"/backlog "Laten we X bouwen"/plan "Plan geaccepteerd"/uitvoeren (operator test)/ft-cycle "FT's afgesloten"/afsluiten

Voor nu nog geen grote winst. Discipline en CLAUDE.md doen al veel. Ik herzie het maandelijks — zodra een skill écht het verschil zou maken, dán pas implementeer ik 'm.

Wat verder

Plugins — buiten Claude's eigen wereld.

Aurono Labs

Een plugin geeft Claude Code toegang tot tools die het zelf niet heeft — een browser, een database, een externe API. Skills zijn instructies; plugins zijn capaciteiten.

concept

Wat is een plugin?

Een extern programma dat via het MCP-protocol zijn tools beschikbaar maakt voor Claude Code. Eenmalig geconfigureerd, daarna aanroepbaar zoals elke andere tool. Configuratie staat in .claude/settings.json, dus de hele werkomgeving reist mee met de repo.

in gebruik

Playwright — design in de browser

De plugin die ik nu gebruik. Claude opent de site in een echte browser, klikt rond, neemt screenshots, en vergelijkt het beeld met design_system.md. Eerste design-check zonder dat ik er zelf naar hoef te kijken.

Wat dit verder kan worden voor Aurono
  • User journeys (login, order placement, fee preview) headless laten draaien in fase 4 van de workflow.
  • Postgres-plugin om event taxonomie en payloads tegen echte data te toetsen.
  • Exchange-API-plugin (Binance, Coinbase) voor live contract-checks van orderstromen.
  • Linear- of GitHub-plugin om fase 1 (idee-intake) direct aan ticketing te koppelen.
